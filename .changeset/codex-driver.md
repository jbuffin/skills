Codex teammates can be launched, re-tasked, watched, tailed and closed. `agent-teammates` has a Codex driver (`scripts/drivers/codex`) with `launch`, `send`, `status`, `tail`, `stop` and `preflight`. Each turn runs as `codex exec` or `codex exec resume` in its own background process group; read-only roles get a read-only sandbox and the driver writes their report marker after a completed turn, writers get workspace-write with network access and the run's `reports/` directory. `launch-teammate.sh --role <role>` now hands `EFFORT_<ROLE>` to the driver's `launch` as `TEAMMATE_EFFORT` (empty without `--role`); the Claude driver ignores it and its launch is unchanged. The Codex preflight checks the `~/.codex/rules` prefix rules the roles need and fails with the exact line to add.

`watch-teammates.sh --until-event <max-min> <team-dir>` is a bounded run for a coordinator with no Monitor tool: it polls once a minute, exits 0 right after the poll that printed an event, or prints `WATCH timeout <max-min>` after that many polls. Its BLOCKED counts and alert times persist in `<team-dir>/.watch-state`, so reruns neither repeat a DONE nor reset the BLOCKED and 10-minute rules. A read-only Codex teammate's launch prompt now says its sandbox is read-only and that its final message is its report. `launch-teammate.sh`'s usage text no longer describes only Claude.

The Codex driver hardens read-only reports and `stop`: codex writes the report to a private path in the team directory, and the wrapper renames it and the marker into `reports/` so a planted symlink is replaced rather than followed. `stop` also ends tool commands that run in their own process group. The preflight ignores commented-out rules, reads `decision` by name, and fails a needed command that a `forbidden` or `prompt` rule covers.
