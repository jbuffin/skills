Commodore no longer stops to ask before it pushes or marks a PR ready. The agent pushes the run's own branches through `push-branch.sh` and opens, marks ready and comments on the run's own PRs without a call. Posts and settings outside the run's own branches and PRs stay high-stakes. The `Push` / `Don't push` push-approval item, added in the unreleased finding-cards change, is removed again, and so is the pr-feedback `Post` / `Don't post` item for runs with no fixes: the findings-item approval releases the pushes and the replies, and the replies post once CI is green. The `Rerun` item stays.

The default ground rule is now "PRs end ready for review; nothing is merged except through auto-merge where the repo allows it". PRs still open as drafts. At Phase 3 step 4 the agent runs `pr-ready.sh` with autopilot on or off and marks ready every PR the run opened whose unit and lower stack units are closed, `human` findings included. `pr-ready.sh` prints `run: gh pr ready` for any open draft PR and prints `run: gh pr merge --auto` only when autopilot is on, `ADMIRAL_AUTO_MERGE` is set and the PR is clean; otherwise it prints `no auto-merge: <url>: <reason>`. It exits 1 with `not ready:` when the PR isn't open. An autopilot build run takes the recommended defaults after phase 1 and runs to the end; missing secrets, security stops, product and scope calls and "no security role skill" still stop it. Every build run's phase 1 drafts allow rules for `pr-ready.sh` and `gh pr ready`.
