`agent-teammates` has a Copilot CLI driver (`scripts/drivers/copilot/`), so a run with `HARNESS=copilot` in `team.env` can launch, re-task, watch, tail and close Copilot teammates. It is turn-based (`LIVE_MESSAGING=0`, `SEND=script`): each turn is a `copilot -p` run in its own process group with a fixed `--session-id`, and `retask.sh` resumes that session. Every run passes a trimmed `--available-tools` list and `--no-ask-user`. Read-only roles get no write tools, and the driver saves their final message as `reports/<name>.md` and touches the marker. Writer roles get `--allow-all-tools` with pushes, PR merges and creates, `gh api` and `gh issue` denied. These flags are guardrails, not a sandbox: the new `references/harness-copilot.md` covers the current setup (`HARNESS=copilot` set by hand) and the security caveats, including that a read-only teammate can write into the team directory through `git log --output=`. The preflight fails when `copilot` is missing or a headless turn prints nothing, and there is no advisor probe, so `team-preflight.sh` prints `ADVISOR n/a (copilot)`. Detection and the `team-init.sh` defaults come later; Claude behaviour is unchanged.
