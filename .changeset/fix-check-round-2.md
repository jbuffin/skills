Review round 2 is now a fix check, run by a new read-only `fix-checker` role in place of a second reviewer. `review-round.sh` names `u<unit>-fix-checker` in round 2. The fix checker gets the fix range `<reviewed SHA>..HEAD` and the fix job, runs no role skills, sub-agents or advisor calls, and reports each fix-job item as `fixed`, `partly` or `not fixed`, what the fixes introduced, and up to five "seen in passing" notes. Only a HIGH the fixes introduced blocks. Other things the fixes introduced and unfixed items go to a human as `status=human`; notes are recorded `status=open` and never block auto-merge. The coordinator never re-tasks the implementer for a fix-check result or carries one into a later unit. `role-skills.sh` lists `fix-checker` with no skills and drops an override naming it with a `WARN`; `roles-draft.sh` and setup-commodore don't offer it. `team-init.sh` writes `MODEL_FIX_CHECKER` (and `EFFORT_FIX_CHECKER` where the harness uses effort) on each harness's implementer model. A `team.env` from before this change needs `MODEL_FIX_CHECKER` added, set to the run's implementer model, before a fix checker launches. The harness references list the role as read-only with no `.proof`.
